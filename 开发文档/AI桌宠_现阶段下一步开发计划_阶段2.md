## 1. 直接结论：现在先完成哪个模块？

**先完成「AI 接入模块」，具体是：AI 配置、HTTP 接入、非流式请求客户端、设置页连通测试。**

第一项可见成果应当是：

> 在「偏好设置 → AI 设置」填入接口基础地址、模型名和 API Key，点击「测试连接」，能得到一次真实的模型回复；失败时能说明是配置错误、权限限制、认证失败还是网络问题。

### 3.1 必须完成

- [ ] AI 设置：接口基础地址、模型名、Key 输入、保存非敏感配置、测试连接、清除 Key。
- [ ] 经 `@tauri-apps/plugin-http` 完成非流式文本请求。
- [ ] 一只默认宠物的稳定身份、名字、人格与模型关联。
- [ ] 聊天消息展示、上下文管理、防重复发送、取消、手动重试、清空会话。
- [ ] 超时、权限拒绝、认证失败、限流、服务端异常、非法响应的处理。
- [ ] 原有桌宠功能回归，以及下文规定的安全与数据边界。

### 3.2 明确不做

本轮不做 SSE 流式解析、真正的说话动画、心情/精力/亲密度、定时衰减、睡觉和生病、语音、向量数据库、长期记忆提取、账号登录、云同步、好友、联机对战、宠物之间学习、手机端、位置捕捉、AR、工具调用、屏幕读取或电脑控制。

`petId` 只解决未来会话、状态和记忆归属的基础问题，不代表本轮需要注册用户、服务器或完整多宠物界面。

### 3.3 一句话验收

> 用户启动桌宠，配置 AI，双击宠物后可以连续进行非流式问答；错误和取消不会卡住；隐藏后再打开聊天窗口仍保留本次会话；正常退出重启后，宠物身份和非敏感配置仍在，Key 需要重新输入。

**本轮故意不承诺：跨重启保留聊天内容、宠物已经具备长期记忆、模型已学会新能力。**

## 4. 按顺序执行的开发任务

### 任务 2.0：基线确认与必要隔离

**目的：避免新功能尚未接入，就先破坏原有窗口、权限、存档或更新行为。**

#### 操作要求

1. 检查 `git status`、当前分支与提交。保留用户已有修改，不执行强制重置、不自动覆盖本地文件。
2. 在独立开发分支工作。先运行原版本，记录聊天入口、拖动、缩放、穿透、模型切换、键鼠联动是否正常；已存在的问题单独登记。
3. 为开发版使用独立的应用标识和数据位置，避免与原 BongoCat 混用。可采用项目自有标识，如 `com.chsljryyds.aipet.dev`；这是建议值，不是已存在配置。不要删除原作者的版权与致谢。
4. 开发期停用原项目自动更新的检查和安装入口，覆盖自动与手动触发。当前配置仍含原项目更新地址、公钥和应用标识。不能只修改 `autoCheck` 的默认值，也不能直接卸载 updater 却留下会报错的调用。正式自有更新体系留到产品化阶段。`[R4]`、`[R5]`、`[R8]`
5. 按窗口梳理权限。现有 `default.json` 使用 `windows: ["*"]`，且包含宽泛文件权限；新增一个受限的 `chat.json` 不会自动抵消它。应同步调整旧配置的匹配范围，或明确列出启用的能力集合。Tauri 会合并同一窗口适用的 capabilities。`[R9]`、`[D2]`

#### 权限收紧时的注意事项

`App.vue` 当前会为多个窗口运行公共初始化。不能只删除聊天窗的文件权限，却继续在它的初始化路径调用需要这些权限的模型初始化逻辑。先区分公共主题/语言/窗口逻辑与主窗专属的模型、设备初始化，再收紧能力。`[R7]`

本轮要求是：聊天窗不因接 AI 获得全盘文件读写或任意程序执行权限。原有模型导入仍可在对应窗口继续工作。不要为了本轮接入，对全部系统功能做无关重构。

#### 完成条件

- [ ] 原有基础功能的测试结果已记录。
- [ ] 开发版不会调用原项目更新链路。
- [ ] 聊天窗启动、主题、语言与关闭/重新打开正常。
- [ ] 权限调整没有破坏模型导入和桌宠展示。

#### 2.1.2 非敏感配置约定

建议数据结构：

```ts
export interface AIConfig {
  schemaVersion: 1
  baseURL: string
  model: string
  timeoutMs: number
  maxContextRounds: number
}
```

本轮建议 `timeoutMs` 初始值为 `60000`，`maxContextRounds` 为 `10`。这些是工程默认值，不是模型性能、兼容性或上下文容量保证。

`baseURL` 与 `model` 由用户填写，不写死账号、真实 Key 或某个必然可用的模型名。首次未配置时，提示前往 AI 设置，而不是自动尝试联网。

**人格 Prompt 不作为模型资源文件的附属配置。**任务 2.2 建立宠物档案后，将人格归入当前宠物；连接测试使用固定的无私人信息短消息即可。

#### 2.1.3 Key 处理，本轮采用一个明确方案

本轮 Key 仅保存于 Rust 进程内存，不使用普通 Pinia 持久化、不写入 JSON 文件、不放入 `localStorage`、日志、Git、错误报告或共享事件载荷。

建议提供三个最小命令：设置/替换 Key、读取本次请求所需 Key、清除 Key。命令从 Tauri 注入的真实窗口上下文检查调用方，只允许必要的 `preference` 和 `chat`，不相信前端传来的「我是哪个窗口」字符串。必要时配合应用命令权限声明；注册命令不意味着它已自动按窗口隔离。`[D2]`

Key 必须与规范化后的接口基础地址绑定。修改接口地址后，要求重新确认或重新输入 Key，不把旧服务的凭证自动发送给新域名。

设置页保存后清空 Key 输入框中的可见草稿，仅显示「本次运行已配置」。聊天发送时临时取用 Key，不把它写入会话状态。所有应用窗口退出后，内存 Key 随进程结束失效。

**这只是避免普通存档中的明文凭证，不是完整的密钥保险箱，也不能防止已控制本机的攻击者读取进程内存。**跨重启免输入应另接操作系统凭证库或可靠加密方案，并进行独立验收。

#### 2.1.4 HTTP 接入要求

按 Tauri 官方接入流程补齐前端依赖、Rust 依赖、插件初始化和 URL 权限。可以使用：

```bash
pnpm tauri add http
```

执行后审查生成的 diff 和锁文件，不盲目接受对所有窗口、所有地址的放行。官方 HTTP 插件通过 Rust 发起请求，但目标 URL 仍需要符合 scope；仅安装插件或声明 `http:default` 不等于所有地址已经获准。`[D1]`

**本轮地址策略：** 开发构建先只允许开发者明确配置用于联调的 HTTPS API 地址；本机 mock 可单独允许指定回环地址和端口。AI 设置支持修改已授权范围内的基础地址。填写任意新地址不会自动修改原生权限，不在范围内时明确提示。

任意服务商地址的运行时授权，是后续产品化问题；本轮不以放开全部 HTTP/HTTPS 来掩盖它。联调前由执行者记录本次允许的服务端地址，未提供真实凭证时先用 mock，不虚构真实连通结果。

建议禁止自动重定向，保留 TLS 证书校验。地址或证书不正确时显示错误，不通过关闭安全校验来「修好」网络。

#### 2.1.5 BaseURL 约定

界面名称统一为「接口基础地址 BaseURL」，最终路径由客户端追加 `/chat/completions`。

| 输入示例                                      | 处理结果                                           |
| --------------------------------------------- | -------------------------------------------------- |
| `https://api.example.com/v1`                  | 请求 `https://api.example.com/v1/chat/completions` |
| `https://api.example.com/v1/`                 | 规范化后与上一项相同                               |
| `https://api.example.com/custom/v1`           | 保留已有路径前缀，再追加 `/chat/completions`       |
| `https://api.example.com/v1/chat/completions` | 提示用户填写基础地址，不再重复拼接                 |
| 空字符串、无协议地址、带用户名密码的 URL      | 阻止发送并给出表单错误                             |

示例域名只是格式示意，不是真实接口配置。不要自动补 `/v1`，不要用以 `/` 开头的相对路径意外覆盖用户已有路径前缀；本轮不支持含查询参数或片段的基础地址。

#### 2.1.6 非流式请求客户端

`src/utils/ai.ts` 只负责协议与网络，不操作 Vue 组件，不直接写聊天列表，也不调用 Live2D。

建议职责拆分为：`normalizeBaseURL`、`validateAIConfig`、`chatOnce`、`testConnection`。可按现有代码风格调整函数名，但保留边界。

请求使用 V2 指定的 Chat Completions 兼容格式：`model`、`messages`、`stream: false`。第一轮只支持纯文本；不添加工具调用、图片或无必要的采样参数。`[V2，第六节]`

响应至少检查 HTTP 状态与 `choices[0].message.content`。本轮只接收非空文本；缺少字段、返回 HTML、结构不匹配时报告「响应格式不支持」，不要直接把对象转成字符串展示。服务端返回明确的截断标记时，提示回复可能未完整结束。

总耗时限制与用户取消共用可中止的请求机制，取消必须传递到 HTTP 插件，不只是把按钮复位。`signal` 和连接超时是插件支持的接口，但总超时仍要覆盖等待响应与读取响应体。`[D1]`

#### 2.1.7 测试连接与错误处理

测试按钮使用当前表单草稿，发送一条固定短消息，不携带聊天历史或私人内容。测试可能消耗服务商额度，按钮旁明确提示。页面加载、切换设置项、编辑输入框时不自动请求。

测试成功不自动覆盖已保存配置；保存是单独动作。测试失败也不清空原配置。请求运行期间防止重复测试，允许取消。

| 场景                    | 用户反馈原则                                                   |
| ----------------------- | -------------------------------------------------------------- |
| 参数为空或 URL 不合法   | 在表单就地提示，不发请求                                       |
| HTTP 权限拒绝           | 提示目标地址未获当前构建授权，不笼统归咎于网络                 |
| 401 / 403               | 提示凭证或访问权限需要检查，不展示 Authorization               |
| 404                     | 提示核对基础地址、接口路径和模型；不能仅凭状态码断言模型不存在 |
| 429                     | 提示可能限流或额度受限，以脱敏后的服务端信息辅助判断           |
| 5xx、断网、DNS/TLS 错误 | 使用可理解提示，保留安全的诊断分类                             |
| 超时                    | 明确「请求超时」，释放请求状态                                 |
| 用户取消                | 明确「已取消」，不作为系统错误                                 |
| 非 JSON 或结构不支持    | 明确说明响应格式不匹配                                         |

错误映射表是本轮产品处理建议，不保证各兼容服务商对状态码的具体使用完全一致。禁止直接展示或记录完整请求对象、原始响应头、原始错误堆栈中的敏感字段。

### 任务 2.2：最小宠物身份，不建设完整养成

**目标：让后续会话属于「这一只宠物」，而不是绑定到某个 Live2D 文件夹。**

新增 `src/types/pet.ts`、`src/stores/pet.ts`，并在必要的初始化位置接入。

建议结构：

```ts
export interface PetProfile {
  schemaVersion: 1
  id: string
  name: string
  modelId: string | null
  personality: string
  createdAt: string
}
```

本轮只维护一只默认宠物。无需 `ownerId`、物种图鉴、属性克制、稀有度、等级或云端数据库。使用项目已存在的 ID 工具即可，不引入新 ID 服务。`[R1]`

#### 数据规则

- `id` 首次创建后保持不变；名字、人格和外观修改都不重建 ID。
- `modelId` 引用现有模型管理中的资源 ID，不能拿资源 ID 代替宠物 ID。
- 人格属于 `PetProfile`。任务 2.1 的设置页可增加一个简洁的「当前宠物」区域编辑名字与人格，不另建完整档案中心。
- 删除或丢失展示模型时回退到可用模型，保留宠物身份和人格。
- 正常退出重启后恢复档案；不承诺本轮尚未实现的聊天历史恢复。

#### 多窗口初始化要求

由 `main` 在持久化状态加载完成后，执行幂等的「不存在则创建默认宠物」。`chat`、`preference` 等待已有档案同步，不能各自生成默认宠物。

启动同步与初始化失败时应提供可见提示，不悄悄创建第二个 ID。新 store 按仓库实际锁定插件版本接入；不复制整个 store 作为第二套永久数据来源。

现有 `modelStore.currentModel` 继续服务桌面渲染。确定一个明确的绑定更新方向，例如由主窗在模型切换成功后更新 `pet.modelId`，不要建立两个互相触发、循环覆盖的 watcher。

- [ ] 打开三个窗口、重复打开聊天窗，不产生新 ID。

- [ ] 模型不可用时保留档案并回退展示。

### 任务 2.3：会话管理与聊天界面

**目标：复用 2.1 的客户端，把当前禁用的占位聊天页改成可用的非流式聊天。**

主要修改或新增：`src/stores/chat.ts`、`src/types/chat.ts`、`src/pages/chat/index.vue`，以及相应测试文件。

#### 2.3.1 数据分层

| 数据                                   | 本轮存放方式                                            |
| -------------------------------------- | ------------------------------------------------------- |
| 接口地址、模型与请求策略               | `ai` store，非敏感持久化                                |
| 宠物 ID、名字、人格、模型关联          | `pet` store，持久化                                     |
| Key                                    | Rust 进程内存，不进入上述 store                         |
| 当前聊天消息                           | `chat` 窗口内存，本轮不跨重启持久化                     |
| `AbortController`、Promise、请求运行态 | 非序列化的运行时变量，不保存、不跨窗广播                |
| 未来动画指令                           | 后续阶段使用单独的宠物状态事件，不传 Key 或私人聊天全文 |

特别注意：当前全局插件启用了 `saveOnChange`。本轮 `chat` 的临时消息和运行态应明确排除保存；核对 3.x 插件的启动、过滤和禁保存接口，不仅仅设置 `saveOnChange: false`。插件文档还描述了正常退出时保存的行为，因此「关闭变更时保存」不能直接等同于「永不落盘」。`[R7]`、`[D3]`

#### 2.3.2 建议消息结构

```ts
export type MessageStatus = 'pending' | 'complete' | 'failed' | 'cancelled'

export interface ChatMessage {
  id: string
  petId: string
  conversationId: string
  turnId: string
  role: 'user' | 'assistant'
  content: string
  status: MessageStatus
  createdAt: string
}
```

`requestId`、当前取消控制器和会话版本号另作运行态管理，用于区分重试和忽略过期结果。系统人格在组装请求时加入，不作为用户可见的普通聊天气泡，也不允许模型回复修改真实配置或执行本机操作。

#### 2.3.3 发送流程

```text
等待 AI 配置和宠物档案就绪
  → 校验输入与本轮 Key
  → 取得本次请求的配置、人格和 petId 快照
  → 为本轮生成 turnId、requestId
  → 追加一条用户消息，显示等待状态
  → 组装有效上下文
  → 调用 chatOnce，stream=false
  → 成功：一次性显示完整回复，标记本轮完成
  → 失败：保留用户问题，显示错误与手动重试入口
  → 取消：保留用户问题，标记取消，允许重新发送
  → 最终清理本请求的运行态
```

清理必须核对 `requestId`，防止旧请求的 `finally` 把新请求的发送状态清掉。

**本轮没有逐字输出，也不制造假的流式打字动画来冒充真实流式。**等待回复时显示加载状态，响应结束后一次展示文本即可。

#### 2.3.4 上下文规则

初版上下文采用：**当前宠物人格 + 最近 N 轮成功完成的用户/助手对话 + 本次用户输入**。默认 `N=10` 只是限制条数的策略，不等于准确控制 token 数。

失败、取消和连接测试记录不进入正式上下文。重试同一问题不能再次追加一份用户消息；前一轮失败后开始的新问题，也不应把残留的错误气泡当作助手回答送给模型。

组装请求时先保留系统人格和本次问题，再从最近成功对话中截取完整轮次。不要破坏用户/助手配对。超出服务商上下文限制时提示清空或缩短内容，不通过无提示地丢掉当前问题来凑长度。

`petId` 已绑定到会话，但此阶段没有多宠物切换界面，也没有跨设备身份认证。不要因预留一个字段就声明上述能力已经具备。

#### 2.3.5 取消、重试、清空、配置变化

| 操作                      | 本轮明确行为                                                         |
| ------------------------- | -------------------------------------------------------------------- |
| 重复点击发送              | 同一聊天窗口只允许一个在途发送请求，不重复扣费请求                   |
| 取消                      | 中止客户端请求，标记已取消；迟到的响应不再写入消息                   |
| 手动重试                  | 复用原问题与轮次，创建新 `requestId`，不重复追加用户消息             |
| 清空会话                  | 取消在途请求并递增会话版本；清空消息，防止旧响应重新出现             |
| 隐藏聊天窗口              | 保留本次运行会话，允许在途请求按原超时规则结束；重新打开可以继续查看 |
| 退出应用或销毁聊天页面    | 终止本地在途任务；下次启动不恢复「正在发送」状态                     |
| 请求期间修改 AI 设置/人格 | 在途请求使用发送时的快照，新配置只影响下一次发送                     |

不做静默自动重试。重复请求可能产生额外费用；取消客户端等待也不保证服务端立即停止计算或停止计费，因此界面不作此类承诺。

#### 2.3.6 界面要求

保留现有透明无边框窗口、拖动区域、关闭行为和双击入口，不重新实现一套聊天窗口。

界面需要：用户与宠物消息区分、加载提示、发送/取消按钮、错误信息、手动重试、清空会话、未配置提示。中文输入法选词阶段的 Enter 不发送；普通 Enter 发送，Shift+Enter 换行。

本轮使用纯文本安全渲染。不要使用 `v-html` 展示模型回复；不自动加载回复中的远程图片，不执行模型产生的脚本、工具或命令。代码块高亮、复杂 Markdown 和文件附件以后再做。

新增文本应纳入项目现有语言机制；至少检查中文显示与默认语言回退，不破坏现有主题和布局。

#### 完成条件

- [ ] 双击宠物后可以真实发送和接收回复。
- [ ] 连续 5 轮问答后仍可正常继续；请求组装测试证明有效上下文已携带。
- [ ] 取消、失败重试、清空、隐藏再打开、修改设置等路径符合上表。
- [ ] 没有把聊天记录持久化成未经说明的新功能，也没有保存 Key。

## 5. 模块边界：避免后面返工

以下为本轮建议的数据职责，不表示需要立即建立大型架构：

```text
preference / AI 设置
  ├─ 非敏感配置 → ai store
  ├─ 当前宠物属性 → pet store
  └─ Key → 进程内存凭证管理

chat / 聊天页面
  → chat store 编排单次发送
  → 读取配置快照 + 宠物人格 + 当前有效上下文
  → utils/ai.ts
  → Tauri HTTP 插件
  → 用户指定且已授权的兼容 API

main / 桌宠主窗口
  → 继续负责 Live2D、键鼠、窗口与现有展示逻辑
  → 本轮只补默认宠物初始化与必要模型关联
  → 真正的对话状态动画在阶段 4 接入
```

**不得越界：** Vue 页面不直接堆协议解析；AI 客户端不修改模型参数；模型返回文本不修改权限和数值；Key 不进入同步 store；请求对象和渲染器实例不参与持久化。

普通配置优先复用项目已接入的同步机制。未来的动作事件只表达「哪只宠物、哪个请求、进入哪个状态」，不把整个配置、Key 或完整私人对话塞入事件。动画渲染实例仍只由主窗口管理。`[V2，第四节]`、`[R3]`、`[D3]`
